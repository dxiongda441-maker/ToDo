# 読書ログ 設計書（ドラフト）

ToDo アプリの「履歴（カレンダー）」をライフログとして扱い、そこに読書の振り返り・アウトプット機能を追加するための設計です。
まだ実装はしていません。この内容で良いかを確認してから作り始めます。

---

## 0. 前提

- **「ライフログ」はこのリポジトリの ToDo アプリを指す**と想定しています。今のアプリには「その日に作成・完了・削除したタスク」をカレンダーで振り返る履歴機能があり、これを「日々の記録＝ライフログ」の土台にします。
  - 別のライフログアプリを指している場合は教えてください。リポジトリ内のどのブランチにも「lifelog / ライフログ」という名前のコードは見つかりませんでした。
- 今のアプリの作りに合わせます：素の HTML / CSS / JavaScript で、サーバーは使わず、データはブラウザの `localStorage` に保存し、JSON でバックアップします。GitHub Pages で公開します。

## 1. リサーチ：みんなはどうやって読書記録をしているか

### 1-1. 読み方・まとめ方の手法

| 手法 | 中身 | 設計に取り入れる点 |
|---|---|---|
| **SQ3R**（Robinson, 1941） | Survey（ざっと見る）→ Question（問いを立てる）→ Read（読む）→ Recite（自分の言葉で言い直す）→ Review（見直す） | 読む前に**問い**を立て、読みながら答えを探し、読み終えたら**問いに答える**流れにする |
| **点検読書**（Adler『本を読む本』） | 精読の前に目次・序文・結論を数分眺め、本の構造をつかむ | 読む前の欄に「目次を見て気になる章」を書けるようにする |
| **読む前に予想を書く**（日本の読書ノート教材） | 読む理由・きっかけ・予想を先に書き、読後に本の内容とのズレを見る | 「予想」と「実際」を読了時に並べて表示する |
| **自分の言葉で書く** | 読了後すぐ他人のレビューを見ず、自分の感じ方を残す | 引用（本の言葉）と自分の考えを別の欄に分ける |
| **段階的要約**（Tiago Forte） | 読書中のメモ → 見直しで大事な所に印 → さらに絞る | 章メモの中で「特に重要」に★を付けられ、読了時の「3つの学び」はそこから選べる |
| **1冊1ノート＋読書ログ**（Obsidian の読書ノート運用など） | 本ごとのノートに書誌・章メモ・引用を集め、別に日々の読書ログを付ける | 「本のノート」と「日付ごとの記録（ライフログ）」を分けて持ち、日付から本へ飛べるようにする |

### 1-2. 既存サービス

| サービス | 特徴 | 参考にする点 / しない点 |
|---|---|---|
| ブクログ | 表紙を並べた本棚、バーコード登録、評価・感想・タグ、自分だけの読書メモ | 本棚の見た目、状態（読みたい / 読んでる / 読んだ）、タグ |
| 読書メーター | 読んだ冊数・ページ数のグラフ、読書仲間との交流、4種類の本棚 | 月ごとの冊数・ページ数の集計。交流機能は取り入れない（個人用のため） |
| Goodreads / StoryGraph（海外） | 本棚の状態管理、年間目標、評価とレビュー | 年間の冊数目標は後回しの候補 |
| Obsidian ＋ Readwise（海外） | Kindle のハイライトを自動で取り込み、本ごとのノートにまとめる | 引用を「ページ番号つき」で残す形。自動取り込みはサーバーが必要なので今回はしない |

**既存サービスとの違い**：多くのサービスは「読んだ本の記録と感想」が中心で、**読む前の問い → 章ごとのまとめ → 問いへの答え → 行動**という学びの流れまで一続きで扱うものは少ないです。ここをこのツールの軸にします。

## 2. 基本の考え方（設計方針）

1. **読む前・読んでいる途中・読み終えた後の3段階**で、それぞれ書く欄を用意する。
2. **読む前の問いに、読み終えてから答える**。ここが振り返りの中心。
3. **章ごとに「キーワード・学んだこと・要約」を短く書ける**。書くことが重荷にならないよう、どの欄も空のままで保存できる。
4. **学んだことを行動に変える**。読了時に書いた「やってみること」を、ボタン1つで ToDo に追加できる（ToDo アプリとつなげる意味がここで出る）。
5. **ライフログのカレンダーに読書の記録も出る**。「この日は何をして、何を読んで、何を学んだか」が1か所で見られる。
6. スマホ幅でも書きやすい画面にする（今のアプリと同じ方針）。

## 3. 記録する項目

### 3-1. 書誌情報（本の基本データ）

| 項目 | 必須 | 備考 |
|---|---|---|
| 題名 | ○ | |
| 副題 | | |
| 著者名 | ○ | 複数人に対応（共著・訳者） |
| 訳者 | | 翻訳書の場合 |
| 出版社 | | |
| 発行年 | | 西暦。必要なら月まで |
| ISBN | | 入れると書誌の自動入力ができる（4章） |
| ページ数 | | 進み具合の表示に使う |
| 形式 | | 紙 / 電子 / オーディオブック |
| ジャンル・タグ | | 例：「ビジネス」「歴史」「仕事で使う」 |
| 状態 | ○ | 読みたい / 読んでいる / 読了 / 中断 / やめた |
| 日付 | 自動 | 登録日・読み始めた日・読み終えた日 |

### 3-2. 読む前（読書前メモ）

| 項目 | 問いかけの例 |
|---|---|
| きっかけ | この本をどこで知った？なぜ今読む？ |
| この本から学びたいこと（問い） | 「この本を読んで答えを出したい問い」を1〜3個。例：「チームの会議を短くするには？」 |
| 予想 | 読む前に、どんなことが書いてあると思う？ |
| 気になる章 | 目次を見て、特に読みたい章 |

### 3-3. 読んでいる途中（章ごとのメモ）

章（または読んだ範囲）ごとに1枚のカードを作ります。

| 項目 | 備考 |
|---|---|
| 章の番号・章の題名 | 章に分かれていない本は「p.1〜40」のように範囲でもよい |
| 重要なキーワード | タグのように複数入力。後で本をまたいで検索できる |
| 学んだこと | 箇条書き。特に大事なものには★を付けられる |
| 要約 | 2〜3行で、自分の言葉で |
| 引用 | 心に残った文と**ページ番号** |
| 自分の考え・疑問 | 引用とは分けて書く |
| 問いとのつながり | 読む前の問いのどれに関係するかを選べる（任意） |
| 読んだ日 | 自動。ライフログのカレンダーに出る |

### 3-4. 読み終えた後（振り返り）

| 項目 | 備考 |
|---|---|
| 一言でいうと | この本を一文で要約 |
| 問いへの答え | 読む前に立てた問いが並んで表示され、それぞれに答えを書く |
| 予想と実際 | 読む前の予想を表示し、その横に「実際はどうだったか」を書く |
| 3つの学び | 章メモの★から選ぶか、新しく書く |
| やってみること | 行動に移すこと。**「ToDoに追加」ボタン**でタスク化 |
| 評価 | 1〜5 |
| 感想 | 自由記述 |
| 誰に薦めたいか | 任意 |

### 3-5. 後日の振り返り（任意）

読了から1週間後・1か月後などに「この本の学びを実際に使えたか」を短く追記できる欄。読了日から一定日数たった本を、読書画面の上に「振り返りどき」として出します（通知は出さない）。

## 4. 書誌情報の入れ方

- **基本は手入力**。題名・著者だけ入れればすぐ始められるようにする。
- **ISBN からの自動入力はおまけ機能**にする。ISBN（本の裏の 978 で始まる13桁）を入れて「取得」を押すと、題名・著者・出版社・発行年・ページ数を埋める。
  - 日本の本：**openBD**（無料・登録不要、日本の出版物の書誌データ）をまず使う。
  - 見つからなければ **Google Books API** を使う。
  - **注意**：openBD は「バージョン1の提供終了」が告知されたことがあり、Google Books は登録なしで使うと1日の利用回数の上限に当たりやすいです（こちらの環境で試したところ、上限超過のエラーが返りました）。どちらも、いつ使えなくなるか分からない前提で、**取得に失敗しても手入力で続けられる**ようにします。実装時に、公開しているページから実際に動くかを確かめます。
- バーコードをカメラで読む機能は、対応ブラウザが限られるため後回しにします。

## 5. 画面の設計

### 5-1. 全体の構成

画面上部に切り替えのタブを置きます。

```
[ ToDo ] [ 読書 ] [ ライフログ ]
```

- **ToDo**：今の画面（タスクの追加・一覧）
- **読書**：本棚と本ごとのノート
- **ライフログ**：今の「履歴」カレンダー。タスクと読書の記録を日付ごとにまとめて表示

### 5-2. 読書タブ：本棚

```
┌──────────────────────────────┐
│ 読書                [＋ 本を追加] │
│ [読んでいる 2][読みたい 5][読了 12] │
│ 🔍 題名・著者・キーワードで検索       │
├──────────────────────────────┤
│ 📖 『○○○○』 著者名 (2023)          │
│    第3章まで ▓▓▓▓░░░ 120/300p      │
│    最近のメモ：11/14                │
├──────────────────────────────┤
│ 📖 『△△△△』 著者名 (2019)          │
│    読む前メモだけ                    │
└──────────────────────────────┘
```

### 5-3. 本のノート（1冊ごとの画面）

縦に並んだ3つの段で、今どこまで書いたかが分かるようにします。

```
← 本棚へ
『○○○○』 著者名／出版社／2023年
状態：[読んでいる ▼]

① 読む前      ✓ 記入済み    [開く]
   問い：チームの会議を短くするには？

② 章ごとのメモ  3章分        [＋ 章を追加]
   第1章 ○○  #キーワード #キーワード
   第2章 △△  ★2
   第3章 □□

③ 読み終えて    まだ          [振り返りを書く]
```

- 「読み終えて」を開くと、読む前の問いと予想が上に表示され、その下に答えを書く欄が出ます。
- 「やってみること」の横に「ToDoに追加」ボタン。押すと「『○○○○』より：〜」というタスクが ToDo に入ります。

### 5-4. ライフログタブ（今の履歴を広げる）

- カレンダーの日付に、タスクの記録に加えて**読書の記録があった日は印**を付けます（色を分ける）。
- 日付を押すと、その日の記録を種類ごとに表示：
  - 完了したタスク / 追加したタスク / 削除したタスク（今と同じ）
  - **読書**：「『○○○○』第3章のメモ」「『△△△△』を読了」「『□□□□』を読み始めた」→ 押すとその本のノートへ移動
- 月の上部に小さな集計：その月に読了した冊数、書いた章メモの数。

## 6. データの持ち方

今のタスクのデータには手を加えず、本のデータを別の保存場所（`localStorage` のキー `todo.books.v1`）に置きます。

```jsonc
{
  "id": "book_xxx",
  "title": "題名",
  "subtitle": "",
  "authors": ["著者A"],
  "translators": [],
  "publisher": "出版社",
  "publishedYear": 2023,
  "isbn": "9784xxxxxxxxx",
  "pageCount": 300,
  "format": "paper",               // paper | ebook | audio
  "tags": ["ビジネス"],
  "status": "reading",             // want | reading | finished | paused | dropped
  "addedAt": 1731700000000,
  "startedAt": 1731700000000,
  "finishedAt": null,
  "currentPage": 120,

  "before": {
    "trigger": "きっかけ",
    "questions": [{ "id": "q1", "text": "学びたい問い" }],
    "prediction": "予想",
    "focusChapters": "気になる章",
    "writtenAt": 1731700000000
  },

  "chapters": [{
    "id": "ch_xxx",
    "order": 1,
    "title": "第1章 ○○",
    "range": "p.1-40",
    "keywords": ["キーワード"],
    "learnings": [{ "text": "学んだこと", "starred": true }],
    "summary": "要約",
    "quotes": [{ "text": "引用", "page": 23 }],
    "thoughts": "自分の考え・疑問",
    "questionIds": ["q1"],
    "createdAt": 1731700000000,
    "updatedAt": 1731700000000
  }],

  "after": {
    "oneLine": "一言でいうと",
    "answers": [{ "questionId": "q1", "text": "問いへの答え" }],
    "predictionResult": "予想と実際",
    "takeaways": ["学び1", "学び2", "学び3"],
    "actions": [{ "text": "やってみること", "taskId": "ToDoに追加したタスクのid" }],
    "rating": 4,
    "review": "感想",
    "recommendTo": "",
    "writtenAt": null
  },

  "followUps": [{ "at": 1732300000000, "note": "後日の振り返り" }]
}
```

**ライフログへの出し方**：カレンダーは、本のデータの日付（`startedAt` / 章メモの `createdAt` / `finishedAt` / `followUps.at`）を拾って日ごとに並べます。別に「その日の記録」を二重に保存はしません（データがずれないようにするため）。

**バックアップ**：今の JSON バックアップを `version: 2` にして `books` を加えます。

- 古いバックアップ（`version: 1`、本のデータなし）もそのまま読み込める。
- 復元は今と同じ「足し合わせ」方式。同じ id の本は重複させない。
- 文字だけなら `localStorage` の容量（おおよそ 5MB）で数百冊分は入ります。表紙画像は保存しません（必要なら画像の URL だけ）。

## 7. 作る順番

| 段階 | 内容 | ここで使えるようになること |
|---|---|---|
| 1 | タブ切り替え、本の追加（手入力）、本棚、本のノート（読む前・章メモ・読了）、バックアップ v2 | 読書ノートとして一通り使える |
| 2 | ライフログのカレンダーに読書の記録を表示、本のノートへのリンク | 「その日何を読んで何を学んだか」が見える |
| 3 | 「やってみること」→ ToDo に追加、問いへの答えと予想の比較表示 | 学びを行動につなげられる |
| 4 | ISBN からの自動入力、キーワードで本をまたいだ検索、月ごとの集計 | 入力が楽になり、過去の学びを探せる |
| 5（候補） | 後日の振り返り表示、年間の冊数目標、Markdown での書き出し | 読み返しと外部への持ち出し |

各段階ごとに、スマホ幅とパソコン幅の両方で画面を確認してから次に進みます。

## 8. 決めてほしいこと

1. **「ライフログ」はこの ToDo アプリ（の履歴カレンダー）で合っていますか？** 別のアプリなら場所を教えてください。
2. **画面の分け方**：上のタブで「ToDo / 読書 / ライフログ」を切り替える形で良いですか？（今のように1画面に縦に並べる案もあります）
3. **章メモの単位**：章ごとが基本で、「1回読んだ分ごと」でも書けるようにする、で良いですか？
