# まなびログ 設計書

手書きの設計図（ノート p.18）をもとにした設計。実装は `study/` にある。

## 1. 設計図の要件と実装の対応

| 設計図の要件 | 実装 |
|---|---|
| ① 学習・スキル習得を早める。理解度に合わせた難易度で問題を作る（選択・穴埋め・白紙など） | 問題形式は **選択 / 穴埋め / 白紙（記述）/ コード（Python）** の 4 種類。理解度が低いうちは選択、上がると穴埋め → 白紙・コードへ自動で切り替わる（`src/mastery.js` `preferredType`）。難易度 1〜5 は正答率が約 7 割になる難しさを狙う（`targetDifficulty`）。AI を有効にすると、問題集を解き終わった後も Claude が同じ条件で新しい問題を作る（`src/ai.js`） |
| ② 理解度・定着度を数値化する。テストや AI の質問に答える形で | **理解度**（0〜100）= Elo / 項目反応理論方式の実力推定。**定着度**（%）= 間隔反復の想起確率の平均。FE は **予想正答率**（合格ライン 60%）も表示。「実力テスト」モードで点数を記録。白紙問題は AI が採点・添削する（AI がなければ模範解答と比べて自己採点） |
| 成長の実感、できることの確認 | 成長記録画面：理解度の推移グラフ、トピック別の表、実力テストの履歴、14 日間の解答数。解答ごとに「理解度 33 → 41 (+8)」を表示 |
| ③ 他の人にもアプリや Web のツールとして使ってもらう | ビルド不要の静的 Web アプリ（PWA）。どの静的ホスティングにも置ける。データは各自のブラウザに保存、AI は各自の API キーを使う（BYOK）ので、運営側にサーバーや費用はかからない |
| まず FE 合格を目標に | FE は期限付きの目標（既定は今日から 120 日後、計画画面で変更可）。試験日から逆算して「段階学習 70% → 弱点補強 20% → 模試 10%」の計画を作る |
| ワイン・Python・日常英会話も並行して | 4 科目を同時に管理。ホームに科目ごとのカードを並べる |
| 目標が明確なものは期限を設定 | 目標の種類は 3 つ：**期限あり**（逆算計画）/ **期限なし**（段階を順にクリア）/ **目標なし＝探索** |
| 目標が明確でないものは幅広い基礎から始め、目標を後から設定 | ワイン・英会話は「探索」で開始し、触っていないトピックを優先して満遍なく出題。計画画面で候補（J.S.A. ワインエキスパート、WSET Level 2、英検 2 級、TOEIC など）か自由入力で後から目標を設定できる |
| Python は自分でコードを書いて eval 評価できるまで | Python の目標は「自分でコードを書き、eval（評価）を作れるようになる」。最終段階で `accuracy()` / `exact_match()` / `run_eval()` など評価ハーネスを自作する問題を用意。コード問題はブラウザ内の Python（Pyodide）でテストを実行して自動採点する |
| AI で学習ツールを作っている先例を参考に、使えるものは使う | 間隔反復（Anki の SM-2、FSRS の想起確率）、Elo / IRT による実力推定、LLM-as-a-judge（記述式の採点）、Pyodide、Claude の structured outputs を採用。各科目の計画画面に外部教材（IPA 公式、過去問道場、Python 公式チュートリアル、Anki など）を掲載 |
| Claude Code が実装・基盤、Codex がデザインと評価 | `AGENTS.md` に Codex 向けの評価観点とレビュー手順を記載 |
| アプリ本体（コード）とセーブデータを分けて保存 | 本体 = リポジトリのファイル。セーブデータ = localStorage の `gakushu.save`。API キーなどの端末設定は `gakushu.settings` に分け、バックアップに含めない |
| セーブデータにバージョン番号を付け、更新時は「移行」する | `schemaVersion` を持たせ、`src/migrations.js` に 1 段ずつの移行関数を書く。読み込み時に自動移行し、**移行前のデータを `gakushu.save.premigration.v{N}` に退避してから**書き換える。アプリより新しいデータや壊れたデータは上書きせず読み取り専用にする |
| 端末の外にもバックアップ。JSON の書き出しから始め、必要ならクラウド同期 | 設定画面から JSON を書き出し・読み込み。古い形式のバックアップも読み込み時に移行される。7 日以上バックアップしていないとホームで知らせる。クラウド同期は未実装（§5） |

## 2. 構成

```
study/
├── index.html / styles.css / manifest.webmanifest / sw.js / icon.svg
├── src/
│   ├── main.js            起動・画面切り替え（#/home などのハッシュで切り替え）
│   ├── store.js           セーブデータの読み書き・エクスポート・インポート
│   ├── migrations.js      スキーマ移行
│   ├── mastery.js         理解度・定着度・予想正答率
│   ├── srs.js             間隔反復（復習スケジュール）
│   ├── selector.js        次の問題を選ぶ
│   ├── planner.js         学習計画
│   ├── progress.js        解答の記録・連続日数・推移
│   ├── grader.js          機械採点（選択・穴埋め・コード・キーワード）
│   ├── ai.js              Claude API（問題作成・記述式の採点）
│   ├── python/            Pyodide でのコード実行（Web Worker + 採点ハーネス）
│   ├── content/           科目定義と問題バンク（fe / python / wine / english）
│   └── ui/                画面（home / study / plan / progress / settings）
└── tests/                 node --test で動くテスト
```

ロジック（`src/*.js`）は DOM に依存しないので Node で単体テストできる。画面（`src/ui/`）はそれを呼ぶだけにしている。

## 3. 数値化の仕組み

### 理解度（トピックごと、0〜100）

- 問題の難しさ `b = 難易度 × 20 − 10 + 形式補正`（選択 0、穴埋め +5、白紙・コード +10）
- 正答の期待値 `p = 1 / (1 + exp(−(θ − b) / 12))`。4 択は当てずっぽうでも当たるので `0.25 + 0.75p`
- 解答ごとに `θ ← θ + K × 1.5 × (得点 − p)`。K は解答数が少ないうちは大きく、増えると小さくなる（最初は早く動き、だんだん安定する）
- 初期値 30（未測定の間は画面上「未測定」）

### 科目の理解度

トピックの理解度を出題比率（weight）で重み付けした平均。**未着手のトピックは 0** として数えるので、範囲を網羅しないと上がらない。

### 定着度

各問題の復習間隔から想起確率 `R = 0.9^(経過日数 / 間隔)` を出し、解いたことのある問題で平均したもの。復習をさぼると下がる。

### 出題の優先順位

1. 復習期限の来た問題（間違えた問題は 10 分後、正解すると 1 日 → 3 日 → 間隔 × 易しさ係数…）
2. 今日の重点トピックの未出題問題のうち、難易度と形式が理解度に合うもの
3. 問題が尽きたら、AI が理解度に合わせて新しく作る（AI 有効時）

## 4. セーブデータ（schemaVersion 1）

```jsonc
{
  "schemaVersion": 1,
  "subjects":   { "fe": { "enabled": true, "dailyQuota": 20, "goal": { "title", "targetDate", "startDate", "presetId" } } },
  "topics":     { "fe.algo": { "ability": 42.1, "attempts": 12, "scoreSum": 8.5, "lastAt": 0 } },
  "items":      { "fe.algo.003": { "reps", "lapses", "ease", "interval", "due", "lastScore", "lastAt", "seen", "subject", "topic" } },
  "attempts":   [ { "at", "qid", "subject", "topic", "type", "difficulty", "source", "score", "mode", "sessionId" } ],
  "tests":      [ { "at", "subject", "score", "total", "percent", "understanding" } ],
  "daily":      { "2026-10-22": { "fe": { "answered", "scoreSum", "understanding" } } },
  "aiQuestions":{ "<id>": { ...AI が作った問題 } },
  "meta":       { "lastExportAt", "migratedFrom" }
}
```

- 問題バンクの問題 ID は公開後に変えない（復習記録が ID で参照するため）
- 科目やトピックを増やすのはスキーマ変更ではない（`ensureSubjects` が足りない枠を足すだけ）
- 形を変えるときは `SCHEMA_VERSION` を上げて移行関数とテストを追加する（手順は `src/migrations.js` の先頭）

## 5. v0.2 で追加したもの（2 回目の依頼）

| 依頼 | 実装 |
|---|---|
| FE は明日テストをして理解度を測り、その結果で問題を作り直したい | **診断テスト**モード（`src/diagnostic.js`）。全 9 分野から 3 問ずつ（計 27 問）、分野ごとに難易度 2 から始めて正解なら上げ・不正解なら下げる簡易適応型。結果は `tests[]` に `kind: "diagnostic"` と分野別の内訳つきで保存し、以後の計画で苦手分野を重点にする。結果画面の「結果をコピー」で Claude に貼り付けるレポート（Markdown、間違えた問題の ID と解答つき）を出力し、それをもとに問題集へ問題を追加する運用。FE の問題は 76 → 95 問（各分野の難易度の幅を広げた） |
| ワイン・英会話は基礎を網羅的に | 新トピック「ワインの種類・ラベル」「数字・時間・日付」を追加し、各分野に入門問題を追加（ワイン 30 → 49 問、英会話 28 → 46 問）。探索モードは未着手の分野から易しい問題を出す |
| Python は 基礎 → 読める・選べる → 書ける → eval の順に | トピックを技能の段階で再編成（基礎知識 4 分野 / コードを読む / コードを選ぶ / コードを書く・テスト / eval）。`lockStages` により、前の段階の全分野が理解度 60 以上になるまで次の段階の新しい問題は出さない（計画画面から手動で先に進むことも可）。トピックごとに出す形式を固定（例: 「書く」はコード問題だけ）。45 → 91 問。既存の問題 ID は変えずに所属トピックだけ移した |
| 結果を保存し、次回以降その問題を解くときに参考にできるように | 問題ごとの履歴（`questionHistory`）を出題時に「前回× 10/23・1/2 正解」と表示し、解答後に「前回は間違えた問題です。克服しました！」などと比較する。AI が問題を作るときは、その分野の理解度と最近間違えた問題を伝え、弱点を補う問題にする（`recentMistakes`） |
| どこで開いてどう操作するか分からない | アプリ内に「使い方」ページ（`#/help`）と、初回のみホームに「はじめての方へ」カードを追加 |

セーブデータの形式は変えていない（`tests[]` の記録に任意フィールド `kind` / `topics` / `report`、`subjects.<id>` に任意フィールド `unlockedStages` を足しただけで、無い場合も動く）ので `SCHEMA_VERSION` は 1 のまま。

## 6. 今後の候補

- **クラウド同期**: いまは JSON の手動バックアップのみ。次の段階として、利用者自身の Google ドライブに保存する方法（サーバー不要）か、Supabase などで同期する方法が考えられる
- **FE 科目B 形式の長文問題**: 擬似言語のトレース問題を増やす。AI 出題で補えるが、検証済みの問題を問題バンクに増やすほうが確実
- **英会話の音声**: Web Speech API で発音・聞き取り練習
- **AI 問題の品質管理**: いまは利用者が「誤りがあるので削除」できるだけ。正解率が極端な AI 問題を自動で除外するなど
- **共有用のデプロイ**: GitHub Pages / Netlify などに置けばそのまま公開できる
